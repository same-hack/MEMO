会社はどこの国か

参考：URL（会社所在地・Company/Offices）

日本の地図（=日本の地点）に対応しているか

OpenWeather の各APIは基本的に 緯度・経度（lat/lon）で世界中の地点に対して取得する設計です。したがって 日本の地点（日本の地図上での利用）も対応です。
例：One Call API 3.0 は lat lon を必須パラメータとして API 呼び出しを定義しています。
参考：URL（One Call 3.0 呼び出し仕様）

出典（どこからデータ取得しているのか）

OpenWeather は、衛星・レーダー・地上観測（気象局/空港のMETAR等）・数値予報モデルなど複数ソースを統合し、独自処理（品質管理や補正等）を経て提供する旨を説明しています。
参考：URL（Accuracy and quality of weather data / データソースの説明）

また「政府（国の）警報（weather alerts）」については、各国の国家機関等から収集し、統一フォーマットで提供すると説明されています。
参考：URL（Global Weather Alerts の説明）

② 特色（他の“地図系API/地図アプリ統合”観点で何が強いか）
1) “まとめ取り（One Call）” が強い：地図UIで必要な気象要素を1回の呼び出しで束ねやすい

OpenWeather の One Call API 3.0 は、現在・分単位・時間別・日別・警報・（別エンドポイントで）過去などをまとめて扱う「プロダクト概念」として整理されています。
→ 地図の“現在地/進行ルート/到着見込み時刻”に合わせて、画面で必要な粒度を1レスポンスで揃えやすいのがポイントです。
参考：URL（One Call 3.0 のコンセプト/含まれるエンドポイント）

2) 地図に載せやすい“タイル”が公式で揃う：Weather Maps 2.0（タイル）をそのままMapLibre等へ重畳

Weather Maps 2.0 は URL形式で取得できるタイル/レイヤーとして提供され、複数の天気レイヤーを地図に重ねる用途に寄せたAPIです。
参考：URL（Weather maps 2.0 docs）

3) “移動”に寄せたAPIがある：Road Risk（ルート上の点列で、時刻つき気象＋警報）

Road Risk API は ルートを点列（lat, lon, time）として与え、各点の気象と警報を返すコンセプトです。
調査車のルート監視・到着予測時刻に合わせた気象重畳に、考え方としてフィットします（ただし後述の通り地域制限があります）。
参考：URL（Road Risk API concept）

「まとめ取り（One Call）」は同サービスの他APIと違うのか？（結論）

違います。同じOpenWeatherの中でも、One Callは“複数カテゴリの気象要素を1回のAPIでまとめる”思想で作られており、個別API（現在天気・予報・地図タイル・大気汚染など）を別々に叩く設計とは役割が異なります。
参考：URL（One Call 3.0 の “All-in-One / one simple call” の位置づけ）
